# bcdiff — 函数级二进制比对工具（x86-64 ELF / CFG）

给两个 x86-64 ELF 二进制（旧版/新版），自动回答：**改动的到底是哪几个函数、哪几个基本块，新增的是不是边界检查。**

面向的场景是厂商只给新旧两个二进制、不给补丁源码的安全确认：不信任 changelog，直接从机器码还原函数边界与控制流图，按 CFG 结构和指令特征配对，再把差异定位到基本块级别，并识别哪一处改动符合"新增长度/越界/容量检查"的形态。

## 快速开始

```bash
make                       # 构建 build/bcdiff（需要 Capstone）
make samples               # 构建两版测试程序（macOS 上交叉编译出 x86-64 ELF）
make test                  # 跑回归测试（63 项）
make report                # 对样本生成报告并打印路径
```

```bash
./build/bcdiff old.elf new.elf -o report.html --json report.json -v
```

退出码：`0` 无差异，`1` 有差异，`2` 出错——可直接用在脚本/CI 里做门禁。

## 它做了什么

**1. ELF 解析（自实现，不依赖 libelf）**
支持 `EXEC`/`DYN`(PIE)、静态与动态链接、`.symtab`/`.dynsym`、`build-id`、多代码段。只接受小端 x86-64，其余明确报错。

**2. 反汇编（Capstone 5）**
逐指令解码，提取操作数类型、寄存器、立即数、内存寻址、RIP 相对目标，并归类 call/jmp/jcc/ret/间接跳转/填充。

**3. 函数边界恢复**
- 有 `.symtab` 时**以符号为准**，绝不启发式切割——否则对齐填充会被切成"幻影函数"，这是最常见的误报来源。
- 无符号（剥离）时：种子取入口点、直接 `call` 目标、只读数据里的函数指针；沿 CFG 生长；被未覆盖的间隙再做一次按终止指令切分的线性扫描，最后**合并字节相邻的块**（编译器不在函数内部放对齐填充，所以相邻即同函数）。
- 结果：样本程序剥离后恢复出 19/19 个函数，与符号表完全一致。

**4. CFG 恢复**
基本块划分（leadership：入口、分支目标、分支后）、三类后继（顺序/跳转/switch）、**跳转表识别**（`lea`/`cmp`/`movsxd`+`add`+`jmp reg` 形态，读 4/8 字节表并按可执行性校验）、可达性、环数、圈复杂度。

**5. 函数配对**
- 两阶段候选生成：先按指令数窗口 + 助记符/令牌直方图做廉价预筛，每个旧函数只保留前 12 个候选再做完整比对（含 LCS）。1200 函数规模 1.6 秒。
- 相似度是可调权重的加权和（权重和归一化，分数恒在 [0,1]）：

| 特征 | 含义 | 默认权重 |
|---|---|---|
| `name` | 符号名相似度（编辑距离）；剥离二进制自动停用 | 0.32 |
| `seq` | 粗粒度指令序列 LCS（立即数/栈偏移/地址已归一化） | 0.22 |
| `cfg` | 块数、边数、圈复杂度、环数、分支数 | 0.14 |
| `strings` | 引用的字符串/只读常量集合 | 0.10 |
| `imms` | 立即数常量集合 | 0.08 |
| `calls` | 被调函数多重集 | 0.07 |
| `size` | 指令数比例 | 0.04 |
| `mnem` | 助记符直方图 | 0.03 |

- 贪心全局最优 + 邻居交换精修（只在高置信对之外进行）。
- 两遍配对：第一遍配对后给每个函数分配**跨版本一致的规范名**（被调函数按配对结果统一命名），第二遍用规范名重算 call 特征——这样剥离二进制里"地址必然不同"不会污染调用图相似度。
- 调优结论：在"符号 / 剥离 / -O1 重建 / 函数重排"四组数据上做了 41 组随机权重搜索 + 7 组人工对比，**默认权重排名第一**，在可区分函数上配对正确率 100%（见下方"验证"）。

**6. 基本块级差异**
块内指令按**语义令牌**做 LCS 对齐。语义令牌把寄存器、栈帧偏移、分支地址都归一化，只保留"做了什么"（含字符串字面量、常量、被调函数规范名），所以重排/重编译不会制造假差异。

**7. 新增检查识别**
不是"看到 cmp+jcc 就报检查"（那样会把内联 memcpy 的向量化循环报成十几个越界检查）。判定链：
1. 只考察**块对齐后标记为新增的指令**，或整体新增的基本块；
2. 旧函数里已存在同形态 guard 的直接排除；
3. guard 必须是**紧邻**的 cmp/test + jcc；
4. 用 CFG 判定 guard 的**角色**：一侧是"短退出路径"（10 条指令内 return、不写内存、无环），另一侧是"实质工作路径"，才判为校验型 guard；两侧都在干活则视为循环机制，降级为 info；
5. 按形态归类：无符号常量上界 → 长度/越界检查；寄存器对寄存器上界 → 长度-容量检查；`test reg,reg`+零条件 → 空指针检查。
6. 新增的**纯比较叶子函数且被调用** → 判为"引入校验辅助函数"（security）。

## 验证

`make test` 共 63 项断言，覆盖 9 组：

| 组 | 内容 |
|---|---|
| 1–2 | 符号完整版：19/19 函数恢复，精确 3 条 security 发现，无 check-removed 噪声 |
| 3 | 同一文件对比自己：0 差异、退出码 0 |
| 4 | **剥离符号**：函数数、security 种类、被改函数地址与符号版**逐项一致** |
| 5 | **-O1 重建** 与 **函数重排**（含 3 个布局填充函数、8 个函数地址改变）：除真实增删外全部配对上 |
| 6 | 改权重后结论不变（只用名字 / 只用结构） |
| 7 | 400 函数合成目标：398 个未动函数零误报，3 处植入的 `n > 4096` 检查全部命中，0.5 秒 |
| 8 | HTML 结构：38 个 CFG、521 条边端点全部落在节点上、371 个节点零重叠零越界、无 NaN |
| 9 | 错误处理：缺文件/非 ELF/空文件/非法权重/`--help` 退出码 |

手工核对的额外检查：生成的 SVG 几何用脚本验证过——**521 条控制流边全部从节点底边中点出发，371 个节点在 viewBox 内零重叠**。

## 测试样本

`samples/vuln_app.cpp` 一份源码、两个编译开关模拟厂商补丁：

| 版本 | 内容 |
|---|---|
| vulnerable (`v1`) | `parse_record` 无长度检查（`name[32]` 栈溢出）、`copy_token` 忽略 `cap`、存在未使用的 `legacy_decode` |
| patched (`v2`) | `parse_record` 加 `name_len + 1 > sizeof(out->name)` 检查 + 报错路径、`copy_token` 加 `n > cap` 检查、新增 `validate_range` 供 `dispatch` 调用、删除 `legacy_decode` |

工具对这对二进制报出的正是这三处：

```
[security] Length/bounds check added in parse_record      cmp, 0x1f  →  jbe   (0x1f = sizeof(name)-1)
[security] Length-vs-capacity check added in copy_token   cmp reg, reg →  ja
[security] New validation helper validate_range introduced
```

另有 `-O1` 重建版、函数重排版、剥离符号版，以及 `tools/gen_large.sh` 生成的 400 函数规模目标。

## 命令行

```
bcdiff OLD.elf NEW.elf [options]
  -o, --html FILE       HTML 报告路径（默认 bcdiff-report.html）
      --json FILE       同时输出机器可读 JSON
      --weights SPEC    相似度权重，逗号分隔，如 seq=0.3,cfg=0.2,name=0.1
      --threshold X     接受配对的最低分（默认 0.42）
      --no-symbols      忽略符号表，纯结构比对
      --fragment        输入为代码片段（无可用入口点）
      --full            不截断指令输出
  -v, --verbose         进度与各阶段耗时
```

## HTML 报告

单文件、无外部依赖、可离线打开。包含：
- 概览计数（security / 匹配 / 改动 / 增删 / 恢复函数数）与两版二进制的 sha256、build-id、符号状态；
- 按类排序的 findings（含证据：`cmp, 0x1f → jbe 0x20191c`、置信度、涉及地址）；
- 每个函数的**左右并排 CFG**：节点按块深度分行、跳转/回边/switch 边分色，新增块绿、删除块红、改动块黄；
- 块级并排指令差异（`+`/`-` 高亮，左侧旧右侧新，语义对齐后的结果）；
- 每个配对函数的**分数分解**（各特征值与权重）；
- 名称/地址过滤、按状态筛选、全部展开/折叠。

## 已知限制

- **支持 x86-64 小端 ELF**；PE/Mach-O/ARM 不在范围内（架构选择集中在 `src/disasm.cpp`，加架构主要是补 `fill_insn` 的寄存器与跳转语义）。
- **跨优化级别整体重编译**（如 -O1 vs -O2）时，编译器会重排循环、合并常数，单指令级差异不再能支撑"这里加了检查"的断言——此时工具把不确定的 guard 降级为 `info`，只保留形态明确的边界检查。这是刻意的取舍：宁可少报也不误报。
- 间接跳转的跳转表识别依赖常见编译器形态；非常规 dispatch（例如经过二次计算的目标）会退化为"无后继"，此时该块不计入 CFG 边。
- 剥离二进制里**完全同构**的函数（如只差一个常数、或代码字节相同的重复桩函数）本质上不可区分，可能配错——报告里会显示为高相似度的 identical/modified 对，需人工确认。
- 函数签名/调用约定变化（参数从寄存器改为内存传参）会让同一函数相似度显著下降；若低于阈值会显示为 added+removed 对。

## 源码结构

```
src/model.h      数据模型（Binary / Func / Block / Insn / 特征 / 结果）
src/elf.cpp      ELF64 解析、符号、build-id、地址映射
src/disasm.cpp   Capstone 封装、指令语义提取、函数恢复、CFG、跳转表
src/features.cpp 特征提取、相似度、候选生成、配对与精修、权重解析
src/diff.cpp     语义令牌、块对齐、指令对齐、检查识别
src/report.cpp   HTML 报告（含 SVG CFG 布局）
src/json.cpp     JSON 报告
src/util.cpp     SHA-256、序列相似度、转义
tools/           样本构建、额外变体构建、规模目标生成、回归测试
```
